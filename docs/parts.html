Add a part to a page

  1. Link the two main files. They hold every part on the Components and Forms pages, the blocks and the templates.
  2. On pages with charts, a chat or a quiz, or tools, add the optional file after the main script.
  3. Copy the part's markup from its page and change the words. Keep the classes: data-xz-* attributes start each part's behaviour when the page loads.
  4. For markup added later, such as rows loaded from your server, call Xsenze.init(element).
  5. Listen for the xz:* events, or call the methods on a part's element, such as chat.xzChat.jumpTo(id). Each part's table lists them.
  6. Set the theme with data-theme="light" or "dark" on the page or on one section, or make your own on the Create page.
  7. Check the page with the keyboard alone, in both themes, at phone width, and with the script switched off: every part says what it does without it.
    // Ask before a step that is hard to undo.
    if (await Xsenze.confirm({ title: 'Delete Batch B-14?', confirm: 'Delete', danger: true })) deleteBatch();

    // Start parts in markup added later.
    list.insertAdjacentHTML('beforeend', rowsFromServer);
    Xsenze.init(list);

Styling patterns

The same few rules run through every part, so a new part looks and behaves like the rest. Switch the preview to dark to see the states in both themes.

Paid Overdue
PatternHow Xsenze does it
Fill and text in pairsEvery fill has the text colour that reads on it: surface with text, accent with on-accent, inverse with on-inverse, and each status with its -text and -soft forms. A script checks every pair for AA contrast on each build.
FocusA 2px ring in --xz-focus, 2px outside the control, on keyboard focus only (:focus-visible). In dense rows and cells the ring sits inside, so it is never cut off.
Mistakesaria-invalid="true" gives a danger border and ring. The message sits in xz-error and is linked with aria-describedby.
DisabledThe disabled colours rather than see-through ones, so the words stay readable, and a cursor that shows it cannot be used.
Sizes--sm, the default and --lg. On touch screens every control grows to 44px.
StylesModifier classes: --primary, --soft, --ghost, --link, --danger.
StateStyles read the same attributes as screen readers: aria-pressed, aria-expanded, aria-selected, aria-current, open and hidden. is-* classes pin a state for reviews.
Parts of a partBlock and element names, such as xz-card__header, __title, __body, __footer and __actions.
Themesdata-theme="light" or "dark" on the page or on any section; parts inside follow it.
MotionDurations come from --xz-duration-*. Less motion in the system, or the page's motion button, stops movement.
DirectionLogical properties (start and end) in the styles, and arrow keys that follow the text, so layouts mirror in right-to-left text.
No scriptEvery part reads and works without the script: lists stay lists, forms post, details open.
