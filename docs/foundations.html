The values everything is built from

Each value below is a token in tokens/tokens.json and a CSS variable with the --xz- prefix. This page reads the built tokens, so it always matches the code.

Colour

The palette is black and white on pure grey neutrals, one orange for highlights, and four status colours. Use the theme tokens in your styles, not the raw palette, so your screen works in both themes.

Brand

brand-500 is the brand orange. It is the logo colour and the second accent: use it for small highlights and data, such as a featured tag or one series in a chart. Main actions are black in the light theme and white in the dark theme, not orange.

Neutrals

Status

Green means success, amber means warning, rose means error or a destructive action, blue means information. Rose is used for errors because it stays clearly different from the brand orange.

Theme tokens

These names describe a job, and each one has a light and a dark value. The swatches show the theme that is active now. Use the button in the top bar to switch.

Interaction states

The main fill shifts one step toward grey on hover and one more when pressed, and its label stays readable in every state. Disabled controls use the two disabled tokens and no brand colour.

Status tokens

Each status has a fill, a text colour for use on plain surfaces, a soft background and a border.

Contrast

Text pairs meet 4.5:1 and control outlines and focus rings meet 3:1 in both themes. npm run check tests every pair and fails if one drops below the limit.

Do
  • Pair on-accent with accent, and on-accent-2 (dark) with the orange accent-2.
  • Use accent-text for links and accent-2-text for orange text.
  • Pair colour with an icon or a word for status.
Do not
  • Put white text on the brand orange. It fails AA.
  • Use the orange accent-2 as a text colour on light surfaces.
  • Use colour alone to show an error.

Typography

Satoshi is the primary font: headings, buttons, labels and numbers. Space Grotesk is the secondary font: body text and what people type into forms. JetBrains Mono is for code, keyboard keys and token names. All three are bundled with the kit. When a script is not covered, the stack falls back to Noto Sans and then to the system font.

Shape and depth

Radius

Components use a 4px corner: buttons, inputs and badges through radius-control, cards and dialogs through radius-surface. The rest of the scale exists for avatars, chips and products that choose a different look.

Border width

Borders are 1px. Use 2px for the active tab and 4px for the edge of an alert.

Elevation

The kit is flat. Borders separate surfaces, and shadows are kept for things that float above the page: menus, toasts, modals.

Data colours

Eight colours for charts, one per series. Use them in order, so a chart with two series always uses the first two. Each one has a light and a dark value and reaches 3:1 against the surface.

Do
  • Label each series in the chart or its legend, so colour is never the only clue.
  • Use one colour in lighter and darker steps when the data is a single scale, such as low to high.
  • Keep green and red for good and bad only when that is what the data means.
Do not
  • Use more than eight series in one chart. Group the small ones as "Other".
  • Use the status colours as series colours next to real statuses.

Blur

xz-glass gives a bar that floats over content a frosted background. Where the browser cannot blur, it falls back to a solid surface. Tokens: --xz-blur-sm 4px, -md 8px, -lg 16px, -xl 24px.

Illustration and imagery

Pictures should help a person understand or decide. If a picture only fills space, leave it out.

TypeUse it forRules
PhotographsCourses, trainers, places, real productsReal people and settings, natural light, no heavy filters. Crop to one of the aspect ratios above.
IllustrationsEmpty states, onboarding, error pagesLine drawings in the text colour with at most one orange detail. Same 1.75px stroke as the icons.
IconsActions and labelsUse the kit's icon set. Do not use an icon as an illustration by enlarging it past 48px.
AvatarsPeople and organisationsA photo if there is one, initials if not. Never a stock face.
ScreenshotsHelp pages and release notesLight theme, sample data only, no real names, phone numbers or amounts.
Do
  • Write alt text that says what the picture shows. Use empty alt text for decoration.
  • Put the scrim behind any text placed on a photo.
  • Set width, height or an aspect ratio class on every image.
  • Show people from the regions and age groups your product serves.
Do not
  • Put important text inside an image.
  • Mix illustration styles on one screen.
  • Use a photo as a background behind a form or a table.

Icons

Icons are line icons on a 24px grid with a 1.75px stroke and square ends. They take the colour of the text around them. Select an icon to copy its markup.

Accessibility

An icon next to a text label is decoration and is hidden from screen readers. An icon that stands alone needs a name: put aria-label on its button.

Logo

The final logo is still to come. Until then the logo is the name alone, set in Satoshi bold. Use the markup below in headers, or the SVG files in dist/brand/ everywhere else.

Xsenze Xsenze

When the logo image is ready, put it before the name: <img class="xz-logo__mark" src="logo.svg" alt="">. The class sizes it to the text.

Do
  • Keep clear space around the logo equal to half its height.
  • Place it on the page background or a plain surface.
Do not
  • Rotate, stretch or add a shadow.
  • Place it on a photo or a busy background.
  • Set the name in another font or weight.
