Get started

Install the kit

Two files give you everything: one stylesheet and one script. Link them from the CDN, install them with npm, or copy them into your project. There is no build step for HTML and PHP projects.

Quick start

Add two tags to your page. They load the kit from a free CDN, so there is nothing to install or build.

That is the whole setup. Components start by themselves when the page loads.

The version is part of the address
These links point at version __XZ_VERSION__, and that address never changes. Your pages keep working when a new version comes out; change the number when you are ready to update.

Ways to install

Pick one. All three give you the same files.

CDN

The files are served from the kit's GitHub repository by jsDelivr, a free public CDN. It sends the headers that fonts need, so nothing else is required.

The fonts come with the stylesheet: headings in Plus Jakarta Sans, body text in Space Grotesk and code in JetBrains Mono. Nothing else to add.

npm

Install the kit straight from its GitHub release. The package name stays @sfj/ui-kit in your imports.

    npm install __XZ_NPM__
  
    import '@sfj/ui-kit/css';
    import Xsenze from '@sfj/ui-kit';

    // Charts, only where you need them:
    import charts from '@sfj/ui-kit/charts';
    Xsenze.use(charts);

    // Chat and quiz, only where you need them:
    import apps from '@sfj/ui-kit/apps';
    Xsenze.use(apps);

    // Tools (panels, split views, colour and maths), only where you need them:
    import '@sfj/ui-kit/tools.css';
    import tools from '@sfj/ui-kit/tools';
    Xsenze.use(tools);

    // After you add markup to the page later (a route change, an AJAX response):
    Xsenze.init(document.querySelector('#new-content'));

Download

To host the files yourself, build the kit once and copy the dist folder into your project, as in the steps below.

Host the files yourself

1. Build

    git clone __XZ_REPO__.git xsenze-ui-kit
    cd xsenze-ui-kit
    npm install
    npm run build

2. Copy

Copy dist/ to your project, for example to assets/xsenze/. Keep the folder together: the stylesheet loads its fonts from fonts/ next to it.

3. Link

4. The heading font

Headings, buttons and numbers use Plus Jakarta Sans, which comes with the kit. If you have your own copy of Satoshi and want it for headings instead, add <link rel="stylesheet" href="/assets/xsenze/xsenze-satoshi.css"> after the main stylesheet and put Satoshi-Variable.woff2 in the fonts/ folder. Satoshi's licence does not allow passing the file on, so the kit cannot include it.

Without xsenze-satoshi.css, headings use Plus Jakarta Sans. Nothing breaks.

Platforms

The kit is plain HTML, CSS and JavaScript, so it works in any stack. These are the usual places to put the two tags, and how to start components in markup that arrives after the page has loaded.

Plain HTML

Put the tags in the head of each page, as in the quick start. When a script adds markup later, call Xsenze.init(element) on it.

PHP

Put the tags in your shared header file. The version is in the CDN address, so browsers fetch the new files after you update.

Format money and dates on the server the same way the kit does in the browser:

    <?php
    // ₹12,34,567 with lakh and crore grouping. Needs the intl extension.
    $fmt = new NumberFormatter('en_IN', NumberFormatter::DECIMAL);
    echo '₹' . $fmt->format(1234567);

    // 15 Nov 2026
    echo date('j M Y', strtotime('2026-11-15'));

Laravel

Add the tags to your main Blade layout. With Livewire, start components again after each page update.

WordPress

Load the files from your theme's functions.php.

    add_action('wp_enqueue_scripts', function () {
      $cdn = '__XZ_CDN__';
      wp_enqueue_style('xsenze', "$cdn/xsenze.min.css", [], null);
      wp_enqueue_script('xsenze', "$cdn/xsenze.min.js", [], null, ['strategy' => 'defer']);
    });

With a bundler

Install with npm and import the stylesheet and the script once, in your entry file. Importing is safe during server rendering: the kit only touches the page in the browser. Calling Xsenze.init() again is safe too, because each component starts only once.

React and Next.js

    // app/xsenze-kit.jsx, used once in the root layout
    'use client';
    import { useEffect } from 'react';
    import { usePathname } from 'next/navigation';
    import '@sfj/ui-kit/css';

    export default function XsenzeKit() {
      const pathname = usePathname();
      useEffect(() => {
        import('@sfj/ui-kit').then(({ default: Xsenze }) => Xsenze.init());
      }, [pathname]);
      return null;
    }

Vue

    // main.js
    import { createApp, nextTick } from 'vue';
    import '@sfj/ui-kit/css';
    import Xsenze from '@sfj/ui-kit';
    import App from './App.vue';
    import router from './router';

    createApp(App).use(router).mount('#app');
    router.afterEach(() => nextTick(() => Xsenze.init()));

Tokens only

To keep your own components but share the kit's values, load only the variables.

To change a value, edit tokens/tokens.json and run npm run build. Then run npm run check to confirm the colours still meet AA contrast.

Figma library

The Figma library uses the same token names as the code. To create or refresh its variables:

  1. Open the Xsenze UI Kit library file in Figma.
  2. Run a variables import plugin that reads the Design Tokens format.
  3. Choose dist/tokens/tokens.dtcg.json. The core group becomes the primitives collection. The theme group becomes one collection with a Light mode and a Dark mode.
  4. Publish the library so other files receive the update.

Name component properties in Figma after the class modifiers, for example a Button with variant (primary, default, solid, soft, ghost, link, danger) and size (sm, md, lg). Then a design reads the same as its markup.

Themes

Light is the default. Set data-theme on the html element to choose a theme, or on any element to theme just that part of the page.

Markup or callResult
data-theme="light"Light theme.
data-theme="dark"Dark theme.
data-theme="auto"Follows the device setting when the page loads.
data-xz-theme-togglePut this on a button. A click switches the theme and remembers the choice in the browser.
Xsenze.theme.set('dark')Sets and remembers a theme. Also get() and toggle().

Round the corners

Corners are 4px. Two tokens control the corner radius of every component, so a product that needs a square or a softer look can change it in one place.

    :root {
      --xz-radius-control: var(--xz-radius-lg);  /* buttons, inputs, badges */
      --xz-radius-surface: 12px;  /* cards, modals */
    }

Script reference

Most behaviour needs only a data attribute. The script API covers the rest.

CallWhat it does
Xsenze.init(root)Starts components inside root. Call it after adding markup to the page.
Xsenze.toast(options)Shows a toast. Options: title, message, variant, duration, action.
Xsenze.modal.open(target)Opens a modal or drawer. target is a selector or an element. Also close(target).
Xsenze.validate(form)Checks a form, shows messages and returns true when it is valid.
Xsenze.icon(name, options)Returns the SVG markup for an icon. Options: size, label.
Xsenze.format.inr(value)Formats money and dates. See Indian formats.
Xsenze.theme.set(name)Switches the theme.

Browser support

The kit supports the last two versions of Chrome, Edge, Firefox and Safari, on desktop and mobile. It uses the native dialog element and the :has() selector, which need Chrome 105, Firefox 121 or Safari 15.4 and later.
