The rules that make screens built with the kit behave the same way, read the same way and work for everyone.

Accessibility

The kit targets WCAG 2.2 level AA. The components handle the parts below. The parts in the checklist are yours to do on each screen.

What the kit does

  • Contrast. Text is at least 4.5:1 and control outlines and focus rings at least 3:1, in both themes. npm run check tests this.
  • Focus. Every control shows a 2px ring on keyboard focus. Nothing removes the ring.
  • Touch targets. On touch screens, buttons, inputs, menu items and navigation links are at least 44px tall. Checkboxes and radios include their label in the target.
  • Keyboard. Tabs, menus and the combobox use arrow keys, Home, End, Enter and Escape. Modals and drawers hold focus inside and return it when they close.
  • Screen readers. Components set their own roles and states. Toasts and table counts are announced.
  • Motion. Animation stops when the device asks for reduced motion.
  • Zoom. Sizes use rem, so text scales with the browser setting, and layouts reflow down to 320px wide.

Checklist for each screen

  • The page has one h1, and headings go down one level at a time.
  • The page uses header, nav, main and footer, and starts with a skip link (xz-skip-link).
  • Every input has a visible label. A placeholder is not a label.
  • Every icon-only button has an aria-label.
  • Status is never shown by colour alone. Add a word or an icon.
  • Error messages are linked to their field with aria-describedby. Form validation in the kit does this for you.
  • Images have alt text, or alt="" when they are decoration.
  • The html element has the right lang, and text in another language has its own.
  • You can finish the main task using only the keyboard.

Microcopy

Write the way a helpful colleague would speak: plain, short and specific. Many people using Xsenze products read English as a second language, so choose common words.

Basics

  • Sentence case everywhere. "Create account", not "Create Account". Only names take capitals.
  • No full stop on buttons, labels, headings or single-line messages.
  • No exclamation marks.
  • Use the same word for the same thing. If the menu says "Learners", the page title and the button say "learner" too.
  • Address the person as "you". The product is "we" only when it must take responsibility.

Button labels

Start with a verb and name the thing. The label should make sense when read alone.

UseInstead ofWhy

A dialog has one primary button. Put it last, on the right, with "Cancel" before it. For a destructive action use the danger button.
